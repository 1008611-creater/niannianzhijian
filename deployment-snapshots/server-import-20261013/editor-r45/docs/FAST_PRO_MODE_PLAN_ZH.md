# 念念智剪双模式产品方案

## Design Read

这是一个同时接入念念 AI 画布和念念智选工作台的视频创作入口，不是传统剪辑软件首页。用户多数不是剪辑师，他们先关心“我能快速做出哪种可发布视频”，然后才关心时间线、字幕轨、转场和导出参数。

视觉语言应是“创作工作台”：清楚、专业、有视频行业质感，但不要像泛 AI 聊天页，也不要像模板市场堆卡片。

设计参数：

- 变化度：5。稳定、可信，不做花哨营销。
- 动效强度：3。只用在方案选择、进度和预览状态。
- 信息密度：6。比普通消费产品更密，但每屏只服务一个决策。

## 产品目标

把念念智剪做成两个模式，并作为共用剪辑能力接入两个上层项目：

- 念念 AI：主业务是 AI 转绘和 AI 短剧。
- 念念智选：主业务是电商带货和商品内容生产。

- 快速模式：用户选择一个“成片方案”，上传素材，填少量信息，系统生成可预览、可继续编辑的视频工程。
- 专业模式：保留当前完整编辑器，让用户精修时间线、字幕、配音、BGM、效果和导出。

两种模式必须共用同一个真实工程。快速模式不能生成一条不可修改的视频，也不能复制一套新的时间线逻辑。

## 用户应该先看到什么

用户进入念念 AI 画布或念念智选工作台后，不应该先看到“新建项目 / 专业编辑器 / Agent / API”这些工程概念，而应该看到一句明确的问题：

```text
你想做哪种视频？
```

第一屏展示 4 个高价值成片方案，每张方案卡必须包含：

- 成片标题：用户能理解的结果，不是内部模板名。
- 预览结构：例如“开头钩子 -> 卖点讲解 -> 行动引导”。
- 素材要求：需要视频、图片、商品信息还是已有口播。
- 预计结果：时长、平台、是否带字幕、是否带配音。
- 主按钮：直接开始。
- 次按钮：查看样例或进入专业模式。

不要在第一屏展示供应商、模型、Agent 工具、时间线术语、费用明细或复杂参数。

## 快速模式的正确命名

内部可以叫 `template`，但用户界面不要叫“模板”。用户更容易理解这些词：

- 成片方案
- 视频类型
- 发布场景
- 创作目标

推荐 UI 文案：

```text
选择一个成片方案
```

而不是：

```text
选择智能剪辑模板
```

## 第一批高价值成片方案

第一批不按技术能力分，而按用户的真实发布目的分。两个宿主看到的默认排序不同。

### 念念 AI 优先方案

念念 AI 面向 AI 转绘和 AI 短剧，默认不把电商带货放第一位。

#### 1. 短剧片段精修

用户理解：我有短剧片段或剧情素材，想剪成更适合发布的节奏。

适合：

- 短剧片段二创。
- 剧情高光剪辑。
- 角色出场、冲突、反转片段。
- AI 短剧生成后的整理和包装。

前端卡片应展示：

```text
短剧片段精修
把剧情素材剪成“冲突 -> 反转 -> 悬念”的发布版
需要：短剧视频或生成片段、剧情重点
结果：30-90 秒，带字幕、节奏优化、封面标题
```

默认结构：

1. 3 秒冲突或悬念钩子。
2. 关键对白或动作推进。
3. 反转、情绪点或角色高光。
4. 悬念结尾或下一集引导。

#### 2. 转绘素材成片

用户理解：我有 AI 转绘出来的图或视频，希望整理成一条能展示效果的视频。

适合：

- AI 转绘前后对比。
- 角色换装、风格化、场景转绘展示。
- 图生视频片段包装。

前端卡片应展示：

```text
转绘素材成片
把转绘图/视频整理成“原图 -> 转绘 -> 效果展示”的短视频
需要：原素材、转绘结果、展示主题
结果：15-45 秒，带标题、转场、BGM
```

#### 3. 剧情混剪发布版

用户理解：我有多个剧情片段，想剪成一个更完整的故事预告或高光。

适合：

- AI 短剧多片段合成。
- 多角色、多镜头剧情包装。
- 短剧账号发布前整理。

前端卡片应展示：

```text
剧情混剪发布版
把多个片段整理成有开头、有推进、有悬念的短剧预告
需要：多个剧情片段、主角或剧情说明
结果：45-90 秒，带字幕、标题、BGM
```

### 念念智选优先方案

念念智选面向电商带货，商品内容应放在默认第一位。

#### 1. 商品种草短视频

用户理解：我有商品素材，想快速做一条能发抖音/视频号的小广告。

适合：

- 商品展示
- 口播带货
- 探店/开箱/测评素材二次剪辑

前端卡片应展示：

```text
商品种草短视频
把商品素材剪成“痛点 -> 卖点 -> 购买理由”的发布版
需要：商品视频或图片、商品名称、卖点
结果：30-60 秒，带口播、字幕、BGM
```

默认结构：

1. 3 秒痛点或结果钩子。
2. 8-20 秒核心卖点。
3. 5-15 秒使用场景或对比。
4. 3-5 秒行动引导。

这是念念智选的第一优先级，因为它最贴近电商带货、商品内容生产和付费使用场景。

#### 2. 测评口播发布版

用户理解：我拍了一段商品测评口播，想删废话、加字幕、变成能发布的版本。

适合：

- 商品测评。
- 探店口播。
- 开箱讲解。
- 直播切片。

前端卡片应展示：

```text
测评口播发布版
删掉停顿和重复表达，做成清晰的商品测评短视频
需要：带人声的视频、商品名称
结果：节奏更紧、字幕清楚、卖点突出
```

#### 3. 卖点讲解视频

用户理解：我有商品图片或视频，想自动讲清楚卖点。

适合：

- 商品详情讲解。
- 卖点拆解。
- 功能对比。

前端卡片应展示：

```text
卖点讲解视频
围绕商品卖点自动生成讲解、字幕和轻量包装
需要：商品素材、卖点或详情页文字
结果：30-60 秒，带口播、字幕、BGM
```

### 共用方案

两个宿主都可以使用这些通用方案。

#### 1. 无声素材解说视频

用户理解：我有一段没有人声的视频，希望自动加讲解，能发出去。

适合：

- 风景、探店、产品展示、过程记录
- 用户提供的无声素材
- 需要自动口播但不想写稿的人

前端卡片应展示：

```text
无声素材解说视频
自动看画面，生成一段自然口播和字幕
需要：一段视频、想表达的主题
结果：带解说、字幕、轻音乐
```

默认结构：

1. 画面内容总结。
2. 主题化讲解。
3. 节奏化镜头选择。
4. 口播、字幕和 BGM。

这是第二优先级，因为它已经接近当前项目现有能力，能最快做出真实闭环。

#### 2. 口播精剪发布版

用户理解：我拍了一段口播，想删废话、加字幕、变成能发布的版本。

适合：

- 真人口播
- 课程片段
- 产品讲解
- 访谈和直播切片

前端卡片应展示：

```text
口播精剪发布版
删停顿和重复表达，自动生成清晰字幕
需要：带人声的视频
结果：节奏更紧、字幕齐、可继续精修
```

默认结构：

1. 转写并生成真实时间戳。
2. 识别停顿、口头禅、重复表达。
3. 生成可审阅删改方案。
4. 更新字幕和音画同步。

这个方案必须比“无声素材”更谨慎，不能没有词级时间戳就乱剪。

#### 3. 图文素材成片

用户理解：我只有图片、商品图、海报或截图，也想快速生成视频。

适合：

- 商品图
- 案例截图
- 海报/长图
- 多张图片做发布视频

前端卡片应展示：

```text
图文素材成片
把图片和文字做成有节奏的视频
需要：图片、标题或说明
结果：动态标题、转场、配音、BGM
```

默认结构：

1. 图片排序和画面重点识别。
2. 生成标题和分段脚本。
3. 添加运动、字幕和配音。
4. 生成可发布短视频。

这是第三批开发也可以，但第一屏可以先展示为“即将支持”，用来表达产品方向。

## 快速模式首页结构

推荐布局：

```text
顶部：模式切换
  快速成片 | 专业剪辑

主标题：
  你想做哪种视频？

方案区：
  念念 AI：短剧片段精修 / 转绘素材成片 / 剧情混剪发布版 / 共用方案
  念念智选：商品种草短视频 / 测评口播发布版 / 卖点讲解视频 / 共用方案

右侧或下方：
  最近项目
  从专业模式打开
```

方案卡不要做成四张一样的白卡。每张卡应该有不同的信息重心：

- 短剧片段精修：强调冲突、反转、悬念和发布版节奏。
- 转绘素材成片：强调前后对比、视觉变化和展示包装。
- 商品种草：强调卖点结构和发布平台，只在念念智选里默认置顶。
- 无声解说：强调画面理解和口播。
- 口播精剪：强调删停顿、字幕和节奏。
- 图文成片：强调图片动效和标题包装。

## 快速模式二级页面

用户点进一个方案后，只看到这个方案相关的问题。

以“商品种草短视频”为例：

```text
1. 上传素材
   商品视频、图片、已有素材库

2. 填商品信息
   商品名称
   主要卖点
   目标人群
   发布平台

3. 选择风格
   真实测评
   种草推荐
   对比反差
   知识讲解

4. 生成预览
```

不要一次性把所有设置摊开。每个方案最多 3-5 个必填项。

## 风格体系

快速模式必须有“风格”，不是只套流程。

第一批风格建议：

- 真实测评：自然、可信、像真人体验分享。
- 种草推荐：节奏快、卖点明确、适合带货。
- 知识讲解：信息清楚、旁白稳定、适合教程。
- 对比反差：先抛问题或痛点，再给解决方案。

风格影响：

- 脚本结构。
- 口播语气。
- 字幕样式。
- BGM 能量。
- 转场密度。
- 开头钩子类型。

风格不应该只是一个 prompt 字段，必须落到可见的时间线结果里。

## 快速模式和专业模式关系

```text
快速模式 = 选择成片方案 + 少量输入 + 自动生成草稿
专业模式 = 完整时间线编辑 + Agent + 细节控制 + 导出
```

快速模式完成后给用户三个明确动作：

- 继续优化：回到快速模式，重跑某一步。
- 专业剪辑：打开完整编辑器。
- 导出发布：用户明确确认后才导出。

## 共享工程契约

快速模式和专业模式共享：

- `projectId`
- `mode`: `quick` 或 `pro`
- `recipeId`
- `recipeVersion`
- `styleId`
- `workflowRunId`
- `sourceAssetIds`
- `sourceRevision`
- `createdItemIds`
- `createdTrackIds`
- `createdCaptionTrackIds`
- `createdVoiceAssetIds`
- `createdMusicAssetIds`
- `status`
- `failureStep`
- `userInputsSummary`

建议把用户可见的“成片方案”命名为 `recipe`，内部如果继续叫 `template` 也可以，但 UI 层不要暴露模板术语。

## 工作流原则

1. 每个方案是编排器，不是新剪辑引擎。
2. 每个方案最终写入真实时间线。
3. 每次运行都有 `workflowRunId`。
4. 重跑只替换本次运行创建的内容，不动用户手工修改。
5. 失败保留已经完成的素材、脚本、配音和字幕。
6. 进入专业模式后，所有快速模式生成物都能继续编辑。

## 最小执行顺序

### P0：产品与数据契约

- 定义 `quick/pro` 模式。
- 定义 `recipeId`、`styleId`、`workflowRunId`。
- 定义快速模式阶段状态。
- 定义重跑只替换本次运行产物的边界。

### P1：快速模式首页

- 在念念 AI 画布和念念智选工作台中增加“快速成片 / 专业剪辑”切换。
- 做“你想做哪种视频？”方案选择页。
- 按宿主展示不同默认排序。
- 念念 AI 默认展示短剧/转绘方案。
- 念念智选默认展示商品/带货方案。
- 先让“无声素材解说视频”可用，其余可先展示为待开放或灰度。

### P2：方案详情页

- 针对一个方案收集最少输入。
- 上传素材或选择已有素材。
- 选择风格。
- 展示生成阶段。

### P3：打通第一条真实链路

- 先实现“无声素材解说视频”。
- 复用现有粗剪、配音、字幕、BGM 和预检能力。
- 完成后能进入专业模式继续编辑。

### P4：宿主核心方案上线

- 在无声素材链路稳定后，做“商品种草短视频”。
- 同时为念念 AI 做“短剧片段精修”的最小版本。
- 加入商品信息、卖点结构和风格预设。
- 商品种草是念念智选的最高商业价值方案；短剧片段精修是念念 AI 的最高业务贴合方案。

### P5：口播精剪和图文成片

- 口播精剪必须等待真实词级时间戳。
- 图文成片需要更强的视觉包装和动效模板。

## 对应 Skill 路由

```text
画布双模式目标 -> 前端品味路由 -> Design Read / Design Memory -> 快速模式首页规格
视觉和风格要求 -> 前端设计品味 -> 反模板默认 / 信息层级 / 卡片不是堆功能 -> 成片方案卡
工程边界 -> AI 协作边界 -> Codex 唯一工程写入者 -> 本地开发和发布闭环
素材输入 -> 素材导入 -> 去重、上传、等待素材可用 -> 方案运行
人声素材 -> 转写 -> 真实时间戳和文字驱动编辑 -> 口播精剪
无声素材 -> 配音 -> 视频同步旁白 -> 无声解说
BGM 需求 -> 音乐 -> 生成后放置、循环、闪避 -> 成片氛围
结果验收 -> 验证 -> 工程结构证据 + 合成画面证据 -> 可发布草稿
用户确认导出 -> 导出 -> 渲染跟踪和文件交付 -> 发布文件
长期规则 -> 洞察沉淀 -> AGENTS.md / DESIGN.md -> 后续任务自动遵守
```

本方案使用的 Skill：

- `frontend-taste-router`：把双模式当产品 UI，而不是工程清单。
- `design-taste-frontend`：避免泛 AI 卡片页，固定信息层级、密度和视觉语言。
- `ai-native-collaboration`：保持 Codex 为唯一工程写入者，线上由本地发行包发布。
- `chatcut:asset-import`：素材导入、去重和上传状态。
- `chatcut:transcription`：口播视频转写、字幕、停顿清理。
- `chatcut:voice`：无声视频讲解、商品种草口播、短剧包装旁白。
- `chatcut:music`：BGM 生成、放置、循环和闪避。
- `chatcut:verification`：快速模式结果必须用结构和画面证据验证。
- `chatcut:export`：用户明确导出时才渲染交付。
- `insight-to-skill-compounding`：将双模式产品规则沉淀到项目规范。

## 验收标准

1. 用户进入画布后能理解“快速成片”和“专业剪辑”的区别。
2. 用户能通过方案卡判断自己该选哪一个。
3. 每个方案卡都说明结果、适合场景、素材要求和下一步。
4. 快速模式不暴露 API、模型、供应商和时间线术语。
5. 第一个可用方案能生成真实可编辑工程。
6. 快速结果能进入专业模式继续编辑。
7. 重跑不会覆盖用户手工修改。
8. 失败能定位到阶段并允许重试。
9. 字幕和口播必须使用真实时间戳或明确失败。
10. 线上发布仍然走本地构建、完整发行包、回滚和真实浏览器验收。

## 当前不做

- 不做“很多模板”的模板市场。
- 不把快速模式做成一条不可编辑的视频生成结果。
- 不把专业模式裁剪成低配版。
- 不在第一版暴露高级参数。
- 不让普通用户配置 API。
- 不用四张同质化卡片冒充产品设计。
