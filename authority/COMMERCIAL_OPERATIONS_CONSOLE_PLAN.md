# 商业运营台执行合同

## 用户与边界

- 面向个人创作者、小团队和小型企业的月度套餐。
- 每个团队有一份共享积分池；成员不共享登录会话，只有共享的团队额度。
- 管理员维护供应商发布状态、模型、积分价格、月度套餐和团队套餐归属。
- 供应商密钥只存在服务器环境或 Agent Vault，不进入浏览器、项目记录、日志、GitHub 或运营台接口。

## 已实现闭环

1. 普通用户的画布只读取自己团队可见、已发布且服务端运行时准备好的模型和积分价格。
2. 画布创建生成任务后，服务端在供应商提交前以任务标识为幂等键预留积分。
3. 供应商提交明确失败时，服务端立即退款；任务轮询读到失败时，服务端自动退款；成功时结算预留。
4. 预留、结算、退款和管理员调整都保留不可变流水。重复请求不会重复扣款或退款。
5. 管理员只能在 `/admin/commerce/` 查看经过脱敏的供应商状态、模型、套餐、团队余额、积分流水和任务追踪；不显示提示词、密钥或供应商原始响应。
6. 生成任务仍由现有服务器任务链执行，保留 `providerSubmitEnabled=false` 的默认安全边界。运营台不直接调用供应商。

## 状态机

```text
任务准备
  -> 用户确认付费
  -> 服务端预留积分
  -> 提交供应商
       -> 明确提交失败 -> 退款 -> failed
       -> 已接受 -> queued/running
            -> succeeded -> 结算 -> 项目素材 assetId
            -> failed -> 退款 -> 可追踪错误
            -> review -> 保留预留，等待人工核对，不能自动重提
```

网络不确定、供应商账单不确定或没有可靠任务标识时进入 `review`，不会自动退款或重提，避免重复出图和错误结算。

## 月度套餐

- 初始提供“个人创作者月度套餐”和“小团队月度套餐”两个未发布草案。
- 运营人员可设置月度价格、月度积分、可用模型和发布状态；未发布套餐不会暴露给用户。
- 已分配的发布套餐在团队首次读取账户或模型目录时，按“团队 + 套餐 + 自然月”幂等发放一次积分；重复刷新不会重复发放。
- 套餐只能引用已登记模型，草稿套餐不能分配给用户；已分配套餐会把用户模型目录限制在该套餐允许的模型集合内。
- 本阶段不接支付渠道、不伪造订阅成功。支付接入前仍可由管理员通过审计化积分调整完成受控内测。

## 验证清单

1. 普通用户请求管理员接口得到 `403`，请求模型目录时看不到密钥、供应商地址或未发布模型。
2. 管理员修改模型价格和发布状态后，同一团队画布目录读取到正确价格；供应商关闭时模型从用户目录消失。
3. 任务每次只产生一笔预留；明确提交失败只产生一笔退款；完成任务只产生一笔结算。
4. 运营台刷新后，套餐、团队套餐、积分流水和任务追踪持续存在。
5. 桌面端与 390px 移动端访问 `/admin/commerce/`：管理员可见，普通用户和未登录访问被拒绝。

## 未纳入本轮

- 实际支付网关、发票、自动续费和面向用户的购买页，需要在确定支付服务、人民币定价和退款规则后单独实施。
- 本轮不发起任何付费供应商调用，也不修改任何服务器密钥。
