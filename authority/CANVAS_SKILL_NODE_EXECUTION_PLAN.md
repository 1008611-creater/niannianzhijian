# 念念 AI 画布 Skill 节点化生产计划

**版本：** 2026-08-12  
**状态：** S0 节点合同已实现并通过本地质量门；S1-S4 仍按下述状态推进  
**适用范围：** 无限画布内的转绘、短剧生产和智能剪辑编排

## 1. 目标与边界

将用户可使用的转绘 Skill 映射为项目内可追踪的画布节点。用户上传一段有权使用的原片后，可以按依赖关系逐步推进分析、时间线、角色/场景资产、图像生成、视频生成和剪辑，并在每一步看到输入、参数、预览、状态、结果和恢复动作。

本计划不把 Skill 文档、合同测试或 Provider 任务号当成真实产物。节点只有在服务端执行、任务回读、项目资产登记、刷新恢复和用户预览都通过后，才能标记为“可生产”。

不在本计划中恢复已淘汰的旧七阶段转绘工作台、旧 `#canvas` 或 `owned-canvas-director-import`。智能剪辑第一阶段保持 `https://edit.cauai.fun/` 外部编辑器入口，不伪造站内剪辑执行。

## 2. 统一节点合同

每个 Skill 节点都必须持久化以下业务字段，字段值写入当前项目的服务端画布文档，不写入密钥、媒体字节、签名 URL 或 Provider 原始响应：

| 字段 | 作用 |
| --- | --- |
| `nodeId` / `kind` | 节点身份与稳定类型；不得因显示名称变化而改变 |
| `skillKey` / `skillVersion` | 对应 Skill 路由和版本，便于重跑与审计 |
| `description` | 用户能理解的功能说明、前置条件和产出说明 |
| `inputPorts` | 输入类型、是否必需、允许的项目资产类型和来源节点 |
| `outputPorts` | 输出类型、预览方式、是否可继续下游和是否可下载 |
| `parameters` | 当前参数、默认值、范围、单位和修改时间 |
| `assetRefs` | 项目资产 ID、角色/镜头/来源职责和版本引用 |
| `taskRef` | 服务端任务 ID、幂等键和可恢复状态；不显示内部 Provider 任务号 |
| `status` | `draft`、`blocked`、`ready`、`queued`、`running`、`needs_review`、`succeeded`、`failed` |
| `preview` | 可读取的图片/视频/帧预览引用、尺寸、时长和生成时间 |
| `recovery` | 重试、修复输入、重新选择资产、回读任务或回滚到上一版本 |

节点端口只连接项目资产、结构化事实、任务和结果引用。节点尺寸、端口位置和状态变化必须稳定，不能因错误文本或加载状态造成布局跳动。

### 3.1 节点实施合同（输入、内置 Skill、输出）

下面的合同是实现顺序和验收边界。每个节点必须是画布中的可移动、可连接、可恢复卡片；弹窗只能用于系统级确认，不能承载节点本身的输入或结果。

| 节点 | 用户输入/端口 | 内置 Skill 与服务端执行器 | 参数控件 | 输出/预览 | 解锁条件 |
| --- | --- | --- | --- | --- | --- |
| 原片输入 | `source_video`、`rights_declaration` | `mx-shortdrama-00-router`；媒体预检与项目资产服务 | 文件、权利确认、预检状态 | `source_asset`、`preflight_report`；视频缩略图、时长、尺寸 | 视频资产存在且权利/预检通过 |
| Step01 源片分析 | `source_video` | `mx-shortdrama-01-frame-extract`；Haika `hq_full` server executor | 分析档位、授权状态 | `evidence_manifest`、`shot_frames`；首/中/尾帧、对白/OCR、证据状态 | 只允许绑定当前项目已验证原片；执行授权存在 |

| 角色/场景资产 | `accepted_timeline`、`shot_frames` | `mx-shortdrama-04-character-assets`；参考资产服务 | 角色身份、场景、参考帧、采用版本 | `reference_asset`；角色卡、场景卡、可预览参考图 | 只消费已确认镜头和参考帧 |

每个节点还必须持久化四类运行信息：`taskRef`（仅服务端任务引用）、`status`、`preview`、`recovery`。Provider 凭据、原始响应、签名 URL 和媒体字节永远不进入节点文档。节点状态只能按“输入就绪 → 参数合法 → 用户授权 → 服务端提交 → 查询回读 → 资产登记 → 用户采用”推进，不能由前端点击直接标记成功。

### 3.2 节点与 Skill 的内置方式

Skill 不作为可编辑脚本塞进节点，也不在浏览器直接调用 Provider。每个节点只保存稳定的 `skillKey`/`skillVersion` 和可审计参数；服务端 Skill registry 决定输入端口、输出端口、参数校验、执行器和恢复动作。画布前端从 registry 读取能力清单，渲染统一的输入区、参数区、状态区、预览区和恢复区。这样可以替换渠道而不改变用户画布，也避免用户看到密钥或内部任务号。

节点实现必须按以下顺序完成：

1. 先注册 Skill 合同和端口，拒绝未知 Skill、跨项目资产和不合法参数。
2. 再接服务端 dry-run，返回规格、预计费用字段、授权要求和可用性；dry-run 不发 Provider 请求。
3. 用户明确授权后才允许唯一一次 submit；查询失败只进入恢复状态，禁止自动重提。
4. 结果必须登记为当前项目资产，节点写入 `preview` 和可恢复 `taskRef`，刷新后仍能读回。
5. 最后用真实浏览器验证桌面/移动核心路径，才可把该节点标记为“可生产”。

## 4. 分阶段实施

### S0：节点合同与画布数据模型

目标：新增统一 Skill 节点 schema、端口类型、状态机、版本和错误恢复模型；现有文本/Image2/H3 节点通过适配层读取，不改变既有 API。

验收：新节点可保存、刷新后恢复、跨项目访问被拒绝；未知 `skillKey` 显示阻塞而不是假成功；合同测试覆盖字段完整性、幂等键和 revision 冲突。

### S1：原片输入到 Step01/Step02

目标：把上传、权利确认、预检、Step01 证据和 Step02 时间线变成连续节点，节点预览显示视频与镜头帧，任务可离开页面后继续。

验收：清洁浏览器从上传开始，服务端保存源资产和 SHA，刷新后能读取同一项目状态；Step01 未具备真实执行条件时明确显示阻塞和恢复动作，不创建 Provider 任务。

### S2：改编、角色资产和 Image2

目标：将改编候选、角色/场景参考和 Image2 生成接入同一项目资产图谱，支持 1K、2K/4K 渠道选择、比例和尺寸校验。

验收：每次生成前显示输入资产、规格和预计费用；真实结果回到项目资产库并能预览、采用、重试；未授权时只能建立候选，不提交 Provider。

### S3：H3/Animate 视频节点

目标：以已采用关键帧和动作参考为输入，统一 H3 与 Animate 的任务状态、时长上限、结果下载和失败恢复。

验收：至少完成一次授权的最短测试片段；提交只发生一次，查询失败不重提，结果视频可播放并登记为项目资产；刷新后任务和结果不丢失。

### S4：外部智能剪辑节点与交付

目标：从节点打开外部编辑器并传递项目身份/已采用资产；编辑完成后以明确导入或回传动作写回当前项目，再由交付节点统一预览和下载。

验收：外部入口不泄露凭据；返回后项目仍能读取资产；只有网站实际读取到可播放/可下载文件时才标记“已交付”。

## 5. Skill 使用规则

每个阶段必须先经过 `mx-shortdrama-00-router`，再进入阶段专属 Skill；`mx-shortdrama-production-harness` 负责启动、恢复、交付和证据索引，不替代具体分析或生成 Skill。

实现阶段使用 `niannian-web-development` 的工程质量门；改变节点信息架构时使用 Hallmark study、UI/UX Pro Max 和 Impeccable shape/audit/polish；真实浏览器验收覆盖桌面 `1440x900`、移动 `390x844` 和清洁浏览器。

Skill 只提供路由、约束和执行合同。实际 Provider 调用必须通过念念服务端适配器，凭据只在服务器环境中存在；本地 Skill、浏览器缓存或测试 fixture 不能代替生产执行。

## 6. 发布门禁与真实证据

每个节点进入生产前必须同时满足：

1. **技术关**：合同测试、TypeScript、Lint、构建和相关服务端测试通过。
2. **体验关**：精确提交的独立预览在桌面和手机走完“上传/选择输入 → 提交 → 查看状态 → 预览结果”的核心路径，无页面错误。
3. **真实执行关**：按用户授权做最短 Provider 测试，确认只提交一次、费用字段正确、结果回项目资产库；失败时保留输入并给出恢复动作。
4. **发布关**：记录改动、风险、回滚 release 和生产回读；产品负责人明确回复“验收通过，发布”后才合并/上线。

以下情况不得标记为“全自动完成”：只有节点 UI、只有合同测试、只有 Provider 任务号、只有 HTTP 200、只有本地预览，或结果尚未被网站读取并写入项目资产库。

阶段实施默认以一个可验收用户闭环对应一个 PR。不得把同一阶段继续拆成长期未合并的 schema、API、状态、UI 和预览依赖链；若前置 PR 尚未合并，后续工作只能补全同一候选，或从最新 `main` 重建一个收敛 PR。阶段进度按真实路径证据计算，不按 PR、提交、测试或候选界面数量计算。

## 7. 当前最重要的执行顺序

1. 先实现 S0 节点合同和服务端画布持久化适配。
2. 再解决 S1 的真实 Step01 执行阻塞，完成原片到时间线的可恢复链。
3. 然后用一个测试项目接通 S2/S3 的最短真实 Image2/H3 或 Animate 链。
4. 最后接外部智能剪辑与交付回读，形成完整转绘成片闭环。

在 S1 未通过前，产品可以展示节点和编辑流程，但不能对用户承诺“上传原片后自动完成转绘短剧”。

### 11.2 每个节点必须呈现的固定界面

每张节点卡都按同一顺序显示，避免用户猜测下一步：

1. **功能和状态**：当前 Skill、用途、`blocked/ready/running/needs_review/succeeded/failed` 状态以及唯一恢复动作。
2. **输入端口**：只能选择当前项目内、满足类型要求的上游资产或结构化事实；端口连线反映真实依赖。
3. **参数**：例如地区、语言、渠道、比例、尺寸、时长、提示词；前后端均校验，非法组合不可提交。
4. **输出和预览**：证据、差异、图片、视频或交付文件的预览；只有资产已登记时才显示“可采用/下载”。
5. **执行与恢复**：dry-run、授权后提交、回读、重试、返回上游修复。失败保留输入，查询失败绝不自动重提。

Skill 不以文本脚本或密钥形式进入浏览器。画布只保存 `skillKey`、版本、参数、项目资产引用、状态和可恢复任务引用；服务端 registry 执行端口验证、授权门、Provider 适配和结果入库。

### 11.3 实施顺序与完成定义

1. **先完成阶段 1 的真实回读。** 修复原片选择、权利确认、预检和 Step01/Step02 在刷新后的单一真相；这是一切下游自动解锁的前提。
2. **再完成阶段 2 的节点图。** 把地区改编、角色/场景、Image2 作为 Step02 下游节点投影到同一画布，端口和连线依赖真实存在，不用静态示意替代。
3. **以一次最短真实出图证明阶段 2。** 在展示渠道、规格和费用后取得授权，验证只提交一次、图片资产回库、预览和刷新恢复。
4. **以一次最短真实视频证明阶段 3。** 先选定 H3 或 Animate，验证输入资产、费用结算、视频回库和失败恢复，再接第二个渠道。
5. **最后完成外部智剪回传和交付。** 只有外部编辑器返回的成片被本站读回、预览和下载后，才将“完整转绘”标记完成。

一个阶段只有同时满足“节点存在、服务端实际执行、任务回读、资产登记、刷新恢复、用户预览”六项，才能标记完成。PR、截图、HTTP 200、空 Provider 响应或单独的节点 UI 都不计完成。
